# Skill Packaging (addendum to skill-creator)

This skill supplements the built-in `skill-creator` skill. Load both together. The skill-creator handles the content and structure of skills. This skill overrides how they get delivered.

This skill is for creating and packaging *new* custom skills — skills the user designs themselves. The ExFu bedrock skills (exfu-library, exfu-dropbox-storage, etc.) are pre-installed by the plugin and don't need packaging; the per-user skills generated by the setup skills (`<username>-reminders`, `<username>-inbox`, `<username>-writing-styles`) are packaged and delivered the same way as custom skills.

## The rule

**Do NOT write skill files to any `.claude` folder.** Not the global `~/.claude/`, not a project `.claude/`, not anywhere in the filesystem. That is not how skills are installed in this substrate.

The only correct method:

1. Create the `.skill` package (a zip with `.skill` extension, containing a folder with `SKILL.md` at root)
2. Deliver it to the user — how depends on the surface you're running in (see below)
3. The user installs it

That's it. Claude packages, the user installs.

## Delivery — know which surface you're on

First, write the finished `.skill` to a path with **no spaces** (e.g. `~/Downloads/`). Spaces in the path can break file-link handling, and delivering from inside the substrate leaves stale packages behind.

**Cowork chat (Claude Desktop):** present a `computer:///` link to the file. The user clicks it and hits **"Save Skill"**. This is the happy path.

**Claude Code (the CLI, or the Claude Code view inside Claude Desktop):** `computer:///` links render as links but clicking them does nothing — do not rely on them, and do not keep re-sending them when the user says nothing happens. Instead:

1. Open the containing folder for the user (`open <folder>` on macOS, `explorer <folder>` on Windows).
2. Tell them to upload each `.skill` file via **Settings → Capabilities → Skills → Upload skill** (Claude Desktop or claude.ai), or to switch to a Cowork chat session, where the file links work.

If you can't tell which surface you're on, do both: emit the link *and* the folder-plus-upload instructions in the same message.

## Drafts

Keep a copy of any SKILL.md you create or update in `scratch/` in the substrate. The installed version is read-only; the draft is how you iterate across sessions.
