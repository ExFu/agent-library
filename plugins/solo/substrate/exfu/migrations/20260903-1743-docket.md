# Migration: the docket

Follows: exfu/20260903-1825/ontology.md#migrations

## What changes and why

Before this change a scope kept its open matters in three folders of freeform markdown: `todo/` (checkbox lines or a pointer to a task tool), `reminders/` (dated lines) and `inbox/` (one file per captured thought). Scripts guessed at their meaning, the two generations of personal skills disagreed about where the files lived, and an agent paid one read per file to see what was open.

After this migration a scope that chose to convert has one `docket/` folder holding `todo.jsonl`, `reminders.jsonl` and `agent-backlog.jsonl`: one line per entry, one shared record shape, readable in one call from any surface. Dated reminders gain a trigger in `docket/triggers.jsonl` so the dispatcher can fire them. The three old folders are kept intact under `docket/legacy/`. The scope's pin moves to `20260903-1825`. The user's personal reminders and inbox skills are replaced by one docket skill.

This migration is **offered, not imposed**. The deprecated folders remain readable by every shipped reader indefinitely; a scope the user or you decline is recorded `skipped` and keeps working as it is. The whole design is new, so nothing historical needs to be wiped to make room for it.

## Preconditions

Applies when at least one scope holds content in `todo/`, `reminders/` or `inbox/` and has no `docket/`. Use `exfu/derived/index.json`, which lists each scope's `deprecated` folder-types; walk the tree only if the index is missing or stale.

The test is the absence of the target per scope. A scope that already has `docket/` is done, whatever its old folders still contain (they are meant to remain, under `legacy/` or in place). A library whose scopes all have dockets, or none of the three folders, gets `not-applicable`.

Does **not** apply to a library installed at `20260903-1825` or later.

## Instructions

This migration works scope by scope with a journal (see the updater's rules). It writes inside `user/` and `scopes/`, which is why it declares those paths above and carries `requires_user_decision: true`: nothing here runs unattended.

### 1. Discover where the old records really are

Before inventorying scopes, find the files the user's generated skills actually use. Open the installed `<username>-reminders` and `<username>-inbox` skills if present (their source usually sits in `user/skills/`), and read the path each hard-codes. The older generation stored at `databases/reminders/reminders.md` and `databases/inbox/inbox.md`, which the folder-type inventory would never find. Treat those files as that scope's `reminders/` and `inbox/` content.

### 2. Inventory and report

List every candidate scope with what it holds: which of the three folders (or discovered files) have content, how many entries, whether `todo/` is a pointer, and any file whose shape you cannot recognise. Write this inventory under the migration's heading in `durable/ledger/migrations.md` before touching anything.

Say in plain language what will happen, once, for the whole run:

> "Each area of your library keeps its tasks, reminders and captured thoughts in three loose folders. I can gather them into one place, the docket, so they can be read at a glance and reminders can be delivered. I'll go area by area, keep the originals, and skip any area you'd rather leave. Shall we?"

### 3. Convert one scope at a time

For each candidate scope, in the inventory's order, judge whether conversion is doable: the content parses (checkbox lines, dated lines, files with a title line), the user is present, nothing in the folder looks like it means something you do not understand. If not, record the scope `skipped` with the reason and move on; the deprecated shape keeps working.

Otherwise, and only after the user's yes:

1. Count and hash the source files (`shasum` each) and note both in the journal line. Nothing moves until the new files reconcile against these counts.
2. Create `docket/` with `agent.md` from `${CLAUDE_PLUGIN_ROOT}/substrate/templates/scope/docket/agent.md` and `readme.md` from `templates/defaults/docket-readme.md`. Carry every `Local deviations:` line from the old folders' `agent.md` files into the new one as per-file lines (`todo: tracked in ClickUp, not stored locally`, with the connection details preserved). A pointer file gets no local JSONL.
3. Convert, appending one record per entry with a fresh library-wide id (the shape in `ontology.md#records`; `keywords` written by you from the entry's words; `created` from the best evidence, else the file's date; `revision: 1`):
   - `todo/` checkbox lines: `- [ ]` becomes `status: open`, `- [x]` becomes `done` (a `(done YYYY-MM-DD)` note becomes `updated`); entries in `done.md` are `done`. Into `todo.jsonl`.
   - `reminders/` dated lines and `archive.md`: the text after the date is the `title`; the date becomes a trigger in `triggers.jsonl` (`when.mode: once`, `at` that date at 09:00, `tz` the user's zone, `handler.kind: deliver`, `owner` the library's actor, `channel: null`); a rule in words ("every Monday") becomes `cron`; a checked or archived reminder is `status: done` with no trigger. Into `reminders.jsonl`.
   - `inbox/` files and log lines: the first line or the timestamped text is the `title`, the rest is `notes`, a `status:` frontmatter value goes into `agent_notes` as prose. Skip `triage-summary.md`. Into `agent-backlog.jsonl`.
4. Reconcile: the number of records written equals the number of entries counted, and every source hash is unchanged. If not, delete the new JSONL files, record `failed` for the scope, and stop the run.
5. Move the three old folders (and any discovered `databases/reminders/` or `databases/inbox/` files) whole into `docket/legacy/`, preserving names.
6. Set the scope's `exfu:` pin in `scope.md` to `20260903-1825` (the `user/` scope has no pin; leave it).
7. Journal the scope as `converted` with counts, then continue to the next scope.

Every step is idempotent: a `docket/` that already exists with a `legacy/` inside it is a scope that converted; one with JSONL files but no `legacy/` is a scope that failed at step 5, and re-running resumes there.

### 4. Regenerate the personal skill, in the same sitting

If the user had `<username>-reminders` or `<username>-inbox`, run `setup-docket` now, carrying their answers forward (the docket path, the surface-on-load preference, any channel). Package and hand over `<username>-docket`. Tell them plainly that the old two skills are replaced and can be uninstalled; their old files are in `legacy/`, not read by the new skill.

### 5. Update `latest.txt` and the hourly task

Update `exfu/latest.txt` to `20260903-1825` if it names something older. Then check `exfu/derived/agent-registry.json` for the `hourly` cadence: if it is absent, register the shipped `dispatcher`, `docket-compact` and `backlog-sweep` definitions with the install-scheduled-agent skill and tell the user how to create the hourly Desktop task (the scheduled-agents task file explains it). Remove any `inbox-triage` registry entry; `backlog-sweep` replaces it.

### 6. Record the outcome

The migration is `applied` only when every scope the user selected verified. If any selected scope is `failed`, the migration is `failed` and the journal shows exactly which. Scopes the user declined are `skipped` and do not block `applied`.

## Success condition

- Every converted scope has `docket/agent.md`, its entry files, `docket/legacy/` holding the untouched originals, and a pin of `20260903-1825`.
- Record counts reconcile with the inventory for every converted scope.
- The dashboard and the boot skill read the converted scopes through the docket path and the declined ones through the deprecated path.
- If the user had personal reminders or inbox skills, `<username>-docket` is installed and they know the old two are replaced.

## If something goes wrong

Originals are never modified, only moved whole into `legacy/` after reconciliation, so the failure modes are a scope with partial JSONL files (delete them and re-run) or a scope moved to `legacy/` whose pin did not update (set the pin; nothing else is needed). To reverse a scope entirely: move the folders back out of `docket/legacy/`, delete `docket/`, restore the pin, and journal it. Record what happened; leave the rest of the library as found.
