# v0.4 -- the Agent Library re-pitch and the Dropbox migration

Design + implementation plan, validated with Al 2026-07-20. This document is the
anchor for the 0.4.0 release: why the vocabulary changes, exactly what changes and
what deliberately does not, and the ordered work plan.

---

## Why

Two independent triggers landed at the same time:

1. **The pitch wasn't landing.** In conversations with prospective users, "substrate"
   consistently failed to communicate. What *did* land was the librarian idea -- the
   outcome ("my stuff gets organised by librarian agents; I can find things when I
   need them") rather than the implementation ("a scope-based file convention with a
   nightly index"). People don't care how the shelves are managed. They care that the
   library works.

2. **Dropbox's MCP connector gained native `delete` and `move`.** The entire reason
   the Box storage skill was heavy -- no delete, no move, `_trash/` mirroring,
   `_DELETED_` prefixes, a daily cleanup script -- has evaporated. Dropbox also uses
   paths (not numeric folder IDs) and has file revision history. Box is no longer
   the best default for solo storage; it is strictly more machinery for less
   capability.

## How (the shape of the change)

### The two-register vocabulary

The core decision: **rename the pitch, not the plumbing.** Two registers, defined
once in the ontology and used consistently everywhere:

| Term | Register | Meaning |
|---|---|---|
| **ExFu's Agent Library** / "your library" | User-facing | The installed thing: the place your AI's knowledge, skills, and working files live |
| **Agent Librarians** / "your librarians" | User-facing | The ecosystem of scheduled agents that keep the library organised. Always plural |
| **Shelf** | User-facing analogy | Lay term for a scope when teaching new users. An analogy, never a rename |
| **Substrate** | Internal | How the library is implemented: the scope model, folder-types, index, conventions |
| **Scope** | Internal | A bounded working context (a "shelf", loosely, to a new user) |
| **wow** | Both | Unchanged. The user's way of working: the bridge between the agentic internals and their preferences |

**Librarians are deliberately plural.** A singular "your Librarian" character would
set an omniscient-single-agent expectation the mechanics can't honour. The truthful
frame -- and the one that teaches users how the library actually needs managing -- is
an edifice plus an ecosystem: the library is there; you appeal to librarians to
fetch things or do things on your behalf. This framing *is* the discoverability
asymmetry, taught honestly: skills announce themselves; books have to be found
through the catalogue.

Rejected alternatives, for the record: "Agent Librarian OS" (collides with the
existing librarian concept, three stacked abstract nouns, dated jargon); a singular
Librarian character (pretty framing, factual misalignment); a full substrate->library
file rename (839 occurrences across 101 files for zero user-visible benefit once the
two registers exist).

### The one structural rename: `substrate` skill -> `exfu-library`

Skill names and descriptions compete for triggering across every plugin a user has
installed, and "substrate" is a generic token another plugin could plausibly claim.
The boot skill is the front door, so it alone gets renamed: `exfu-library`. The
`exfu-` prefix is the collision guard, and becomes the convention for every *new or
replaced* skill from 0.4 onward. Untouched skills (`scope-setup`, `skill-packaging`,
...) keep their names until the team overhaul provides a natural second batch.

Everything else keeps its name: `plugin/src/shared/substrate/` folder, ontology
anchors, `scope.md` machinery, `git-substrate-sync`, resource filenames
(`the-substrate-primer.md` stays; its *title* changes).

### Storage: Dropbox replaces Box

- New shared skill **`exfu-dropbox-storage`**: local filesystem preferred (Dropbox
  desktop client syncs the folder), Dropbox MCP connector as fallback. Native
  delete/move/copy via the connector; paths, not folder IDs; revision history for
  recovery. The `_trash/` + `_DELETED_` + cleanup machinery is **deleted, not
  ported**.
- Carried caveats, in new form: online-only files need hydration ("Make Available
  Offline"), and sync layers still don't handle symlinks reliably, so
  `exfu/latest.txt` stays. New caveat: Dropbox resolves concurrent edits by writing
  "conflicted copy" files -- surface and reconcile them, never silently pick one.
- **Deleted:** `box-filesystem-management` (shared), `box-cleanup` scheduled task
  (solo), `team-box-folders` (shared). Team-admin's `team-box-folder-provisioning`
  is held pending the team audit verdict rather than replaced blind.
- Convention versioning: the conventions stay **v0.3**. The vocabulary block is an
  additive copy change to `exfu/v0.3/ontology.md`, not a structural revision, so no
  scope repinning and no side-by-side v0.4 base. Plugin version goes to **0.4.0**.

### The migration: `exfu-migrate-to-dropbox`

A shared skill, because it is also the 0.4 upgrade path. It runs against an
installed substrate and, with user confirmation at each destructive step:

1. Verifies the Dropbox copy is complete against the Box original (file count +
   spot checks; Box copy becomes read-only fallback, never edited again).
2. Refreshes the deployed convention base (`exfu/v0.3/`) from the plugin.
3. Rewrites the CLAUDE.md guard: new canonical text referencing `exfu-library`.
4. Repoints and re-pitches the user's wow (paths + vocabulary).
5. Repoints scheduled-task paths and the agent registry; retires the box-cleanup
   registration; removes `_trash/` and any `_DELETED_` strays.
6. Records the storage change in `user/context/`.
7. Emits a checklist of account-side touchpoints it cannot reach (personal
   claude.ai skills that mention the Box path, scheduled task prompts in the
   Claude app).

**Validation discipline:** the first real execution is against Al's live substrate
at `~/Dropbox/ExFu/`. Anything it misses is fixed in the *instruction*, never
patched by hand locally.

## What (ordered work plan)

Versioning note (standing rule): check main's manifest version before bumping.

1. **Convention base re-pitch** -- `exfu/v0.3/ontology.md` (vocabulary block +
   library framing in "The substrate" section), `readme.md`, `principles.md`.
2. **Resources re-pitch** -- `exfu-primer.md`, `the-substrate-primer.md`,
   `substrate-guide.md` (bump its internal version + changelog),
   `ecosystem-references.md` if it mentions Box; 3x `plugin.json` descriptions.
3. **Skill rename** -- `skills/substrate/` -> `skills/exfu-library/`; update name,
   description, guard text, and every reference (wow-template, install skills,
   exfu-start, exfu-guides, ontology, substrate-guide).
4. **Dropbox storage** -- add `exfu-dropbox-storage`; delete
   `box-filesystem-management`, `box-cleanup`, `team-box-folders`; update
   `exfu-library` backend detection (Dropbox path patterns) and verb tables;
   update compliance-briefing.
5. **Install skills** -- solo/team/team-admin + `exfu-start`: library-first
   language, Dropbox as solo default storage.
6. **Dashboard copy** -- generator strings only ("<name>'s library", librarian
   ecosystem framing). Layout changes are a separate, later workstream.
7. **Migration skill** -- `exfu-migrate-to-dropbox` as specified above.
8. **Version + build** -- manifests to 0.4.0, CHANGELOG, `build.sh all`, grep the
   composed output for stale `box-`/`substrate`-skill references.
9. **Live migration run** -- against `~/Dropbox/ExFu/`; fix the instruction, not
   the substrate.
10. **Team audit** -- team + team-admin rot report with a recommendation (bring to
    parity in 0.4.x vs mark deprecated pending demand).
11. **Dashboard improvements** -- proposal list for Al after the vocab pass.

## What this explicitly does not do

- No renaming of `plugin/src/shared/substrate/`, ontology anchors, or resource
  filenames.
- No convention base version bump (stays v0.3).
- No changes to the marketing site (separate pass; the site barely uses
  "substrate").
- No dashboard layout/feature changes in the copy pass.
- No Box support retained: 0.4 is Dropbox/git/local. Box-backed substrates get the
  migration skill, and the old Box folder survives untouched as a fallback.
