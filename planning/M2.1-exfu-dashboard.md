# M2.1 -- ExFu dashboard

A unified visual interface that makes the substrate tangible: scope map, librarian health, and workspace summaries in one browsable HTML page.

**Status:** in progress. A v1 prototype of all three views shipped with M2 phase 2 prototyping and ran against a real 11-scope substrate on 10 June 2026. The four `T3-dashboard-*` plans specify the gap between v1 and this milestone's bar.

---

## Why

The substrate is powerful but invisible. Users interact with it through conversation, never seeing the whole picture at once. The dashboard changes that: open a single HTML file and see your scopes, their health, what's running overnight, and what's on your plate.

This milestone's audience is:
- **Users** who want orientation ("what have I built?") and confidence ("is it working?")
- **Al** who needs a visual proof-of-concept to show prospects what an installed substrate looks like
- **Future agents** that can reference the dashboard as a teaching artefact during install or onboarding

## How

### Sequencing

The dashboard depends on data that M2 produces:
- `exfu/derived/index.json` (from the nightly index, M2 phase 1)
- `exfu/derived/agent-registry.json` (from the scheduled-agent framework, M2 phase 2)
- `exfu/derived/agent-log.json` (from the nightly runner, M2 phase 2)

Implementation can start with the substrate map (which only needs the index) while the librarian framework is being built. The librarian and workspace views follow.

### Process

- Build the generation pipeline first (data in, HTML out)
- Add views incrementally: substrate map, then librarian dashboard, then workspace views
- Each view is a self-contained section of the page; views degrade gracefully if their data source is missing
- Register the dashboard generator as a librarian (nightly cadence, runs after the index)

### What "done" looks like

A user can open a single HTML file from their substrate and see:
- Every scope they have, arranged by relationship, with folder-type population at a glance
- Every librarian, its health, and recent run history
- A summary of their todos, reminders, and inbox items across scopes
- All of this rendered in the ExFu visual language, scannable in seconds

## What

### Deliverables

1. **Substrate map view** -- scope cards with folder-type badges, relationship layout, version pins. Not a file tree; a conceptual map.
2. **Librarian dashboard view** -- registered librarians, health status, run timeline, unregistered definition warnings.
3. **Workspace views** -- read-only summaries of todo, reminders, inbox across scopes. Pointer-aware (shows "managed in ClickUp" for pointer folders).
4. **Generation pipeline** -- Python script (registered as a nightly librarian) that reads the derived data and produces a self-contained HTML file at `exfu/v0.3/visualisations/substrate-dashboard/index.html`.

### Explicitly out of scope

- **Interactive content management.** No creating tasks, dismissing reminders, or triaging inbox from the dashboard. That's what the conversation is for. (Maintenance actions are different: re-run buttons for the index and scheduled jobs entered scope on 10 June 2026 -- see `T3-dashboard-actions.md` -- pending a verified trigger mechanism that runs on the user's subscription allowance.)
- **Real-time updates.** The dashboard is generated on a schedule. It shows the last-known state, not a live feed.
- **Authentication or sharing.** The dashboard is a local file. No login, no hosted version, no multi-user access.

---

## Relationship to M2

M2.1 is a parallel milestone, not a successor. It can progress alongside M2 phase 2 because the substrate map only needs the index (already built). The librarian and workspace views wait for their respective M2 phase 2 deliverables.

The dashboard generator becomes a librarian itself, demonstrating the framework it visualises.
