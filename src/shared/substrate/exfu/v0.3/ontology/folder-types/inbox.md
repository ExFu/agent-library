# Folder type: inbox/

Where uncategorised thoughts go for this scope. The catch-all for things that don't have a home yet.

**Analogy:** a physical inbox tray.

## Default behaviour

When a user says "capture this" or an agent needs to save something and isn't sure where it belongs, it goes in inbox/. The inbox is deliberately unstructured -- its job is to lower the friction of capture, not to organise.

A librarian (the inbox sweep) periodically reviews inbox items and either files them into the right folder-type or asks the user what to do with them.

## Store-or-point

- **Stored:** Markdown files, one per captured thought or item. Named by date or topic.
- **Pointer:** Unusual for inbox/, but possible: "Quick captures go into a Slack channel. This folder tracks what's been triaged."

## Boundaries

- Inbox is for *capture*. Once something is categorised, it moves to the right folder-type: tasks to todo/, documents to docs/, definitions to ontology/, background to context/.
- Inbox is not long-term storage. Items should be triaged regularly. A full inbox is a sign that the sweep librarian needs attention.
