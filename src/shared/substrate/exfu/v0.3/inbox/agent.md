# Inbox

## Why

Capture friction kills good ideas. When a thought, link, or note doesn't have an obvious home, it needs somewhere to land immediately. Inbox/ is that place -- deliberately unstructured, optimised for speed of capture over organisation.

## How

Drop things here. Sort them later. A librarian (inbox sweep) periodically reviews items and triages them to the right folder-type or asks the user what to do.

### Store-or-point

- **Stored:** Markdown files, one per captured item. Named by date or topic.
- **Pointer:** Unusual for inbox/, but possible: "Quick captures go to a Slack channel."

### Boundaries

- Inbox is for *capture*. Once categorised, items move out: tasks to todo/, documents to docs/, definitions to ontology/, background to context/.
- Inbox is not long-term storage. A full inbox means the sweep librarian needs attention.

## What an agent should do

1. When the user says "capture this" or "save this for later" and no specific folder fits, put it here.
2. Name files descriptively enough to triage later.
3. During triage, suggest where items should move based on the folder-type catalogue.
