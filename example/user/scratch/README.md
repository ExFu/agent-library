# user/scratch/

## Purpose

Ephemeral working space for personal in-progress material. Anything that is not ready for a home in `context/`, `databases/`, or a scope, but is worth holding onto temporarily.

## Contents

(Empty in this example.)

Typical contents: half-formed thoughts, draft messages, notes from a call that have not yet been filed, snippets the user wants to come back to. Scratch is forgiving; the librarian will eventually flag stale items, but in the moment anything goes.

## Dependencies

- The cleanup librarian (not shipped in this example) periodically surfaces stale scratch items for the user to decide on: file them, promote them, or delete them.

## Convention

Top-level only. Nested scope folders do not have their own `scratch/`; their working space lives in the scope folder's root or in named subfolders. This rule prevents scratch from spreading across the substrate.

## Why "scratch" and not "notes" or "drafts"

Scratch signals impermanence. Notes and drafts both suggest something that wants to be kept. Scratch lets the user dump without committing to a category; categorising happens later, with the agent's help if needed.
