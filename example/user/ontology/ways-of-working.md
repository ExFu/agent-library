# Ways of working

Personal definitions that apply across all my scopes.

## What "done" means

A task is done when its acceptance criteria are met, verified, and committed. Not when the code is written. Not when tests pass. When it's merged and live.

## How I plan

Three tiers: T1 (overview), T2 (domain plans), T3 (implementation specs). Every plan uses the golden circle: Why it exists, How it works, What it delivers. Milestones (Mn) sequence the work across tiers.

## Communication preferences

- Short by default. Detailed when I ask for it.
- Prose for explanations. Bullets for lists.
- No em-dashes. Commas, semicolons, or full stops.
- No preambles or disclaimers.
