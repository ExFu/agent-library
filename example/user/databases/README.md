# user/databases/

## Purpose

Personal structured records Alastair keeps in the substrate rather than in a SaaS tool. Each database gets its own subfolder.

## Contents

(Empty in this example.)

Common things that might land here as Alastair adopts them: a personal contacts file (light-touch CRM for people not in a third-party system), a reading list, a personal log of decisions made, a brain-dump of ideas to revisit.

## Dependencies

- None currently. As databases are added, each gets its own subfolder with its own README and (where applicable) `agent.md` for the database ontology type.

## Why this folder exists empty

The substrate ships with structural folders pre-created so the user (and the agent) does not have to discover them. An empty `databases/` is more useful than a missing one; when Alastair next mentions "I should keep track of X", the agent has somewhere obvious to put it.
