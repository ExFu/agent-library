# Version resolution

How agents find and read the right convention base for a scope.

## The version pin

Every scope's `scope.md` declares which convention version it follows:

```yaml
exfu: v0.3
```

This tells the agent to read conventions from `exfu/v0.3/`. All `Follows:` references in the scope's agent.md files point into that version directory.

## The `latest` pointer

The substrate root contains a pointer to the current version:

- **Primary:** a symlink at `exfu/latest` pointing to the current version directory (e.g. `v0.3`)
- **Fallback:** a plain text file at `exfu/latest.txt` containing the version directory name on a single line

The fallback exists for environments that don't support symlinks (e.g. Box sync, Windows without developer mode).

## Resolution rules

1. **Scopes with a pin:** read conventions from `exfu/<pin>/`. Ignore `latest`.
2. **user/ scope (no pin):** read conventions through `exfu/latest` (or `latest.txt`).
3. **New scopes:** set their pin to whatever `latest` resolves to at creation time.
4. **After a plugin update:** existing scope pins don't change. New versions install alongside old ones. Migration is an explicit user decision.

## Side-by-side versions

Multiple version directories can coexist:

```
exfu/
  v0.3/
  v0.6/
  latest -> v0.6/
  latest.txt          # "v0.6"
  derived/
```

Old scopes keep reading v0.3. New scopes default to v0.6. Both convention bases are fully functional.

## The `derived/` directory

Generated, unversioned content lives at `exfu/derived/`:

- `index.json` -- the global substrate index (maintained by the nightly index librarian)
- Nothing in derived/ is hand-edited. Everything is generated by librarians or tools.
- Safe to delete and regenerate. It's a cache, not a source of truth.
